# 鼠标与帧节奏稳定性测试（V1.1.2）

2026-10-28。保持2880×1920、HDR10、原有码率和144 fps目标。

## 修改

- 独立光标通道最多保留四个尚未确认的包；确认后发送最新位置，丢弃期间被更新的位置，避免慢USB时在TCP中无限排队过期坐标。单包在途方案在快速移动时会受确认时延限制，已改为小窗口并保持上限。断开／500毫秒无确认仍回退视频内光标；单个在途包仍可能受USB延迟影响。
- 新增光标接收确认往返时间的p50、p95、最大值，统计范围为Mac采样至平板原生接收确认，不包含ArkUI绘制和屏幕扫描。
- 帧调度器对迟到回调保留至少半个目标帧间隔，避免马上发送追赶帧；保留可用的相位，不重复旧帧。现有5／6帧上限和原始帧新鲜度限制不变。

## 验证与限制

- 双端保留之前的签名和画质，Mac测试版使用原固定证书安装；当前工作区同时保留前一轮未发布的平板UI修改。
- 53项JS测试、帧节奏、光标ACK与断线、延迟ACK下丢弃过期位置、管线预算及其他原生回归通过。模拟100 Hz采集、60 Hz目标四秒发送240帧；迟到回调不再紧接追赶帧。
- 旧版HDR动态片段中，筛选采集至少60帧的64个一秒样本，采集65–90 fps、解码提交64–87.9 fps，中位76 fps。编码数接近采集数，说明该片段主要受采集侧限制。
- 新版另一段HDR动态测试中，12个一秒样本解码提交87–111 fps，中位106.5 fps。测试期间窗口内容、遮挡和负载可能不同，不能将差异归因于修改，也不能表示持续锁定目标帧率。
- 新版三个120次确认批次的p95约8.3–10.4 ms，最大值分别约11.7、31.8及46.8 ms；主要包含约100毫秒的闲置心跳，不能作为连续移动鼠标的抖动结论。物理输入到屏幕扫描延迟未测。
- 平板实际激活120 Hz；144 fps目标并不表示屏幕可实际扫描144 Hz。HDR动态帧率与尾部光标延迟仍有波动，尚不能称为稳定达标。需要相同画面、连续真实鼠标操作及长时间热稳定对比；用户在真实快速移动及拖动后反馈“比刚才好很多”；仍需同轨迹、物理端到端延迟及长期热稳定测试。

## API 26 与快速光标复测（2026-10-29）

- 光标确认窗口改为最多四包，保持顺序确认和最新位置优先；延迟确认测试验证上限及恢复。真机部分活跃批次p95约7.5–13 ms，最大值约20–47 ms，仅为采样至平板接收确认，不代表完整鼠标显示延迟。用户反馈快速移动比单包版好很多。
- 平板目标SDK提升至26.0.0，最低兼容保持6.1.1(24)。通过entry元数据开启系统沉浸材质；在HarmonyOS 7平板页面加载后探测state=1、supported=true。系统支持的菜单／滑块／开关使用原生材质，其他自定义区域沿用协调的轻量光影；低版本与其他设备需进一步真机验收。

## 连接初期卡顿排查（2026-10-29）

- 用户反馈刚启动后快速移动光标和拖动窗口卡顿，约 10–30 秒后较流畅；切回原色没有明显改善。
- 将 Mac 光标位置采样从主界面运行循环移到独立高优先级串行队列；光标形状仍在主线程读取，使用锁保护形状快照。保留独立通道的最新位置、在途上限和断线回退。
- 使用固定签名构建安装 Mac 测试版，并在 2880×1920 HDR10、轻度鲜艳及 144 fps 目标下真机重连。用户反馈刚启动快速移动和拖动“更流畅”。
- 测试期间平板报告 120 Hz；部分一秒样本采集约 60–117 fps，编码输出与采集相近，仍有波动。光标确认多数约 5–6 ms，p95 约 8–11 ms，不包括屏幕渲染与扫描。该测试未严格控制移动轨迹或负载，不能认为达到固定帧率，启动阶段变慢的完整原因仍需进一步调查。
- 12-bit 探测：本机低延迟 HEVC 编码器属性列出的最大已确认配置是 10-bit，设置 12-bit 属性返回 -12900；平板 HEVC 硬件能力报告 Main 与 Main10，实际 HDR 缓冲为 P010。不能据此保证 12-bit 端到端输出，因此仍使用已经验证的 HDR10，不做伪升级。
